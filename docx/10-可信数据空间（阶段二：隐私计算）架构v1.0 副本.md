一、 核心技术栈与部署基线
- 计算节点隔离：采用Gramine-SGX（针对高敏感核心算法）和机密容器CoCo（针对大规模联邦学习调度）双轨并行。
- 应用重构（防 OOM 与 TCB 膨胀）：不将Spring Boot单体塞入Enclave。使用GraalVM AOT（Ahead-of-Time）将Java微服务预编译为无外部依赖的静态本地二进制文件（Native Image）。
- KMS 信任根安全：KMS核心组件部署在独占的TEE（如机密虚拟机）中，与计算节点实行双向远程证明（mRA），防止底层管理员窃取密钥。
- 安全信道与硬件证明：采用企业内网自建PCCS的DCAP标准，结合RA-TLS协议。
- 链上链下分工：Fabric链码不直接解析复杂的DCAP Quote，验证逻辑由链下KMS/代理服务执行，链上仅存哈希与寻址指针（胖链下、瘦链上）。

二、 核心流转时序（7步闭环与数据隔离）
1. 任务发起 (API 层)
- 网关接收请求：AssetID, orgId, purpose, AlgorithmHash（即将下发执行的算法二进制摘要）。
2. OPA 策略准入 (< 2ms)
- Service 调用本地 OPA Sidecar，加载基于 PolicyHash 锚定的 Rego 策略。
- OPA 拦截校验：比对 AlgorithmHash 是否存在于数据属主预先审批的白名单中。若拒绝，抛出异常阻断。
3. TEE 环境引导与硬件度量
- 调度系统触发TEE节点分配资源，拉起受保护的计算进程。
- 硬件底层对代码进行密码学度量，生成不可伪造的MRENCLAVE。
- TEE内部生成临时会话密钥对（RSA/ECC），调用硬件指令将公钥哈希写入user_report_data，生成包含硬件签名的DCAP Quote。
4. KMS 安全协商与数据注入 (mRA)
- TEE主动向KMS发起RA-TLS握手，发送包含Quote的X.509证书。
- KMS 通过 PCCS 验证硬件真实性，并严格核对 MRENCLAVE == AlgorithmHash（确保合法算法运行在合法硬件上）。
- KMS 提取 TEE 临时公钥，使用其加密数据解密密钥（DEK）并下发。
- TEE 在内存中解密 DEK，拉取 IPFS 上的数据密文，并在受保护的内存页中解密为明文。
5. 计算结果输出
- TEE 对明文计算完毕后，使用发起方公钥加密结果。
- 计算加密结果的 SHA-256（ResultHash），确保防篡改。
- TEE 清理明文与密钥，安全销毁实例，发布异步回调 。
6. 异步状态机回调 (业务收尾)
- 后端服务消费结果，更新 MySQL 为最终状态，生成 Redis 分布式锁控制防重写 。
7. Fabric 审计存证 (200~800ms)
- 业务服务调用 Fabric 链码 RecordComputation()，将任务流水、哈希与耗时永久固化上链，完成闭环。

三、 长耗时异步调度设计 (RabbitMQ 租约模式)
应对数小时 TEE 计算导致 RabbitMQ 连接断开、消息死循环重发的问题。
- 状态机扩容：MySQL evidence_records 扩展为 8 级精细状态：PENDING -> OPA_APPROVED -> TEE_BOOTING -> KMS_INJECTING -> COMPUTING -> RESULT_SEALED -> FABRIC_COMMITTING -> SUCCESS。
- 任务分发：Spring Boot 发送任务时，在头部注入 reply_to（回调队列名）与 correlation_id。
- 即时确认：TEE 拿到任务立即返回 basic.ack 将消息移出主队列，并向独立微服务“租约管理器 (Lease Manager)”注册进入 PROCESSING。
- 心跳保活：TEE Sidecar 定期发 HTTP/gRPC 心跳续租。无心跳则 LM 将任务推入 DLQ 死信队列 。
- 回调发布：计算完成后，TEE 新建短连接至 RabbitMQ，将结果打入reply_to队列。

四、 OPA 策略升级 (Rego 算法白名单)
部署在每个应用容器旁的 OPA 决策逻辑需更新为以下核心代码：
package dataaccess
default allow := false

allow {
    input.permission == "COMPUTE"
    input.orgId == data.policy.allowedOrg
    input.purpose == data.policy.allowedPurpose
    input.timestamp >= data.policy.validFrom
    input.timestamp <= data.policy.validUntil
    
    # 【新增核心】拦截非法算法注入，强制比对哈希白名单
    input.algorithmHash in data.policy.approvedAlgorithmHashes
}

五、 Fabric 链码数据结构 (Go)
必须实现胖链下、瘦链上，通过复合键实现资产追溯 。
// RecordComputation 定义了隐私计算任务的链上存证结构
type RecordComputation struct {
    DocType         string `json:"docType"`         // CouchDB富查询标识，固定为 "computation_record"
    TaskID          string `json:"taskId"`          // 业务计算任务的唯一标识符
    AssetID         string `json:"assetId"`         // 关联的原始数据资产ID
    OrgID           string `json:"orgId"`           // 发起计算任务的组织MSP标识
    AlgorithmHash   string `json:"algorithmHash"`   // 在TEE内执行算法的SHA-256哈希值 (MRENCLAVE)
    TeeQuoteRef     string `json:"teeQuoteRef"`     // TEE硬件证明(Quote)的链下IPFS指针，避免链上状态膨胀
    ResultHash      string `json:"resultHash"`      // 密文计算结果的哈希值
    ExecutionTimeMs int64  `json:"executionTimeMs"` // 实际执行耗时(毫秒)
    Status          string `json:"status"`          // 计算状态，如 "SUCCESS", "FAILED"
    PolicyHash      string `json:"policyHash"`      // OPA引擎决策依据的策略哈希
    CreatedAt       string `json:"createdAt"`       // RFC3339格式的UTC时间戳
}
