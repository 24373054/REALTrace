1. 架构概述
1.1 设计目标
- 高可用性: 99.9% 可用性，支持故障自动恢复
- 高性能: 支持 5000+ QPS，P99 响应时间<200ms
- 可扩展性: 支持水平扩展，模块化设计
- 安全性: 多层安全防护，数据加密
- 可维护性: 代码清晰，文档完善，易于维护
1.2 架构原则
- 分层架构: 清晰的层次划分，职责明确
- 微服务: 模块化服务，独立部署
- API First: 先设计 API，再实现功能
- DDD 领域驱动: 按业务领域划分模块
- 响应式编程: 异步非阻塞，提高吞吐量

2. 服务架构
2.1 服务划分
用户服务 (User Service)
职责: 用户管理、认证鉴权、权限控制模块:
- 用户注册/登录
- 用户信息管理
- 角色权限管理
- Session 管理
- 2FA 认证
内容服务 (Content Service)
职责: 内容管理、搜索索引、审核流程模块:
- 内容 CRUD
- 内容审核
- 搜索索引
- 标签管理
- 收藏管理
分析服务 (Analytics Service)
职责: 数据分析、区块链分析、风险评估模块:
- 地址分析
- 交易分析
- 风险评分
- 可视化数据
- 报告生成
系统服务 (System Service)
职责: 系统配置、日志监控、任务调度模块:
- 配置管理
- 日志管理
- 监控告警
- 任务调度
- 系统通知
2.2 服务通信
同步通信 (HTTP/REST)
使用场景:
- 服务间直接调用
- API 网关路由
- 外部 API 调用
技术选型: Axios + HTTP/2
异步通信 (Message Queue)
使用场景:
- 事件驱动
- 异步任务
- 服务解耦
技术选型: RabbitMQ + amqplib
gRPC (未来扩展)
使用场景:
- 高性能内部通信
- 微服务间调用
技术选型: gRPC-Node

3. 数据库架构
3.1 数据库设计
PostgreSQL 主数据库
用途: 关系数据、业务数据表分类:
- 用户相关表 (users, roles, permissions)
- 内容相关表 (contents, comments, likes)
- 订单相关表 (orders, payments, invoices)
- 系统相关表 (configs, logs, tasks)
Redis 缓存
用途: 热点数据、Session、队列数据结构:
- String: 缓存、计数器
- Hash: 对象缓存
- List: 消息队列
- Set: 去重、标签
- ZSet: 排行榜、优先级队列
Elasticsearch 搜索引擎
用途: 全文搜索、日志检索、数据分析索引设计:
- content_index: 内容全文搜索
- log_index: 日志检索
- analytics_index: 分析数据

3.3 数据一致性
本地事务
使用场景: 单数据库操作技术: PostgreSQL 事务 (ACID)
分布式事务
使用场景: 跨服务数据一致性方案: Saga 模式 + 补偿事务
最终一致性
使用场景: 非关键数据方案: 消息队列 + 重试机制

4. 核心模块设计
4.1 认证鉴权模块
JWT 认证流程
1. 用户登录 → 验证 credentials
2. 生成 access_token + refresh_token
3. 返回 token 给客户端
4. 客户端请求携带 access_token
5. 服务端验证 token 有效性
6. token 过期使用 refresh_token 刷新

RBAC 权限模型
User → Role → Permission
用户 → 角色 → 权限

权限检查流程:
1. 请求到达
2. 验证 JWT token
3. 获取用户角色
4. 检查角色权限
5. 权限通过 → 执行操作
6. 权限拒绝 → 返回 403

4.2 缓存策略
缓存架构
客户端 → Nginx → API Gateway → Service → Redis → Database
          ↓          ↓            ↓         ↓
      静态缓存   响应缓存    数据缓存   热点数据

缓存策略
- Cache-Aside: 应用级缓存
- Read-Through: 读取时缓存
- Write-Through: 写入时缓存
- Write-Behind: 异步写入
缓存失效
- TTL 过期: 设置过期时间
- 主动失效: 数据更新时失效
- 被动失效: 缓存穿透时回源
4.3 消息队列
使用场景
- 异步任务处理 (报告生成、邮件发送)
- 事件驱动架构 (用户注册、订单创建)
- 峰值流量削峰 (批量导入、数据分析)
- 服务解耦 (通知服务、日志服务)
消息模式
- Point-to-Point: 点对点消息
- Publish-Subscribe: 发布订阅
- Request-Reply: 请求响应
- Competing Consumers: 竞争消费者
可靠性保证
- 消息持久化: 消息存储到磁盘
- 确认机制: ACK 确认收到
- 死信队列: 失败消息处理
- 重试机制: 失败自动重试

5. API 设计
5.1 RESTful API 规范
URL 设计
GET    /api/v1/users              # 获取用户列表
GET    /api/v1/users/:id          # 获取用户详情
POST   /api/v1/users              # 创建用户
PUT    /api/v1/users/:id          # 更新用户
DELETE /api/v1/users/:id          # 删除用户

请求响应格式
请求:
{
  "page": 1,
  "pageSize": 20,
  "filters": {
    "status": "active"
  },
  "sort": {
    "field": "createdAt",
    "order": "desc"
  }
}

响应:
{
  "code": 0,
  "message": "success",
  "data": {
    "list": [],
    "total": 100,
    "page": 1,
    "pageSize": 20
  }
}

错误码设计
0: 成功
1001-1999: 用户相关错误
2001-2999: 内容相关错误
3001-3999: 支付相关错误
4001-4999: 系统相关错误
5001-5999: 未知错误

5.2 API 版本控制
URL 版本控制
/api/v1/users
/api/v2/users

Header 版本控制
Accept: application/vnd.api+v1+json

版本策略
- 向后兼容: v2 兼容 v1
- 废弃通知: 提前 3 个月通知
- 强制迁移: 给予 6 个月过渡期
5.3 API 安全
认证方式
- JWT: 用户认证
- API Key: 服务认证
- OAuth2: 第三方授权
限流策略
- 用户级限流: 每个用户 100 次/分钟
- IP 级限流: 每个 IP 1000 次/分钟
- API 级限流: 每个接口 10000 次/分钟
安全防护
- HTTPS: 传输加密
- CORS: 跨域控制
- CSRF: 跨站请求伪造防护
- XSS: 跨站脚本防护
- SQL 注入: 参数化查询

6. 性能优化
6.1 数据库优化
索引优化
- 主键索引: 自动创建
- 唯一索引: 唯一字段
- 普通索引: 查询字段
- 复合索引: 多字段查询
查询优化
- **避免 SELECT ***: 只查询需要的字段
- 使用 LIMIT: 限制返回数量
- 避免 N+1 查询: 使用 JOIN 或批量查询
- 使用索引: 确保查询使用索引
连接池优化
- 最大连接数: 100
- 最小连接数: 10
- 空闲超时: 30 秒
- 获取超时: 30 秒
6.2 缓存优化
缓存策略
- 热点数据: 永久缓存
- 温数据: TTL 缓存 (1 小时)
- 冷数据: 不缓存
缓存穿透防护
- 布隆过滤器: 快速判断不存在
- 缓存空值: 缓存 null 结果
- 互斥锁: 防止缓存击穿
缓存雪崩防护
- 随机 TTL: 避免同时过期
- 多级缓存: 本地缓存+Redis
- 限流降级: 保护后端服务
6.3 代码优化
异步编程
- Promise: 异步操作
- Async/Await: 异步流程控制
- 事件循环: 非阻塞 IO
性能监控
- APM: 应用性能监控
- 慢查询: 数据库慢查询日志
- 慢接口: API 响应时间监控
- 资源监控: CPU/内存/IO监控

7.2 认证安全
密码安全
- 哈希算法: bcrypt (cost=12)
- 盐值: 随机生成，每次不同
- 复杂度: 至少 8 位，包含大小写字母、数字、特殊字符
Token 安全
- Access Token: 有效期 15 分钟
- Refresh Token: 有效期 7 天
- 存储: HttpOnly Cookie
- 旋转: 每次使用刷新 token
2FA 认证
- TOTP: 时间基于一次性密码
- SMS: 短信验证码
- Email: 邮件验证码
7.3 数据安全
数据加密
- 传输加密: TLS 1.3
- 存储加密: AES-256
- 密钥管理: AWS KMS / HashiCorp Vault
数据脱敏
- 手机号: 138****1234
- 邮箱: a***@example.com
- 身份证: 110101********1234
数据备份
- 全量备份: 每日凌晨 2 点
- 增量备份: 每小时
- 保留策略: 30 天
- 异地备份: 异地灾备中心

8. 监控告警
8.1 监控指标
应用监控
- QPS: 每秒请求数
- 响应时间: P50/P90/P99
- 错误率: 错误请求占比
- 吞吐量: 每秒处理数据量
资源监控
- CPU: 使用率
- 内存: 使用率
- 磁盘: 使用率
- 网络: 入站/出站流量
业务监控
- 用户数: 在线用户、新增用户
- 订单数: 订单量、订单金额
- API 调用: 调用量、成功率
8.2 告警规则
严重告警 (P0)
- 服务不可用
- 数据库连接失败
- 数据丢失
- 安全事件
重要告警 (P1)
- 响应时间>P99
- 错误率>1%
- CPU>90%
- 内存>90%
一般告警 (P2)
- 响应时间>P95
- 错误率>0.5%
- 磁盘>80%
8.3 告警通知
通知渠道
- 邮件: 所有告警
- 短信: P0/P1告警
- 电话: P0 告警
- Webhook: 集成到钉钉/企业微信
告警升级
- P0: 立即通知 → 5 分钟未处理升级 → 15 分钟电话通知
- P1: 立即通知 → 30 分钟未处理升级
- P2: 每小时汇总通知
