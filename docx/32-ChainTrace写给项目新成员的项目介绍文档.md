2. 项目是什么
2.1 ChainTrace 简介
ChainTrace 是一个企业级区块链溯源分析平台，对标国际领先的 Chainalysis 和国内知名的慢雾科技。
核心价值：
- 🔍 专业溯源：多链资产追踪和交易路径分析
- ⚠️ 风险识别：智能识别高风险地址和可疑交易
- 🛡️ 合规支持：帮助企业满足 AML/KYC 监管要求
- 🔓 混币穿透：突破混币器、隐私币等匿名化技术
- 📊 实时监控：7×24 小时链上活动监控和预警
2.2 目标用户
G 端（政府与执法机构）：
- 公安部门网络犯罪侦查
- 金融监管机构
- 反洗钱调查部门
B 端（企业客户）：
- 加密货币交易所
- 区块链项目方
- 金融科技公司
- 安全审计公司
C 端（个人用户）：
- 加密货币投资者
- 区块链研究人员
- 安全从业者
2.3 产品形态
三端架构：
- 管理端（A 端）：系统管理、用户管理、数据管理
- 企业端（B 端）：企业级服务、API 接口、定制功能
- 用户端（C 端）：个人查询、基础分析、报告导出
2.4 竞争优势
vs Chainalysis：
- ✅ 更了解中国市场和监管需求
- ✅ 更具竞争力的定价策略
- ✅ 本地化团队，快速响应
- ✅ 灵活的定制开发能力
vs 慢雾科技：
- ✅ 更强的算法研发能力
- ✅ 更完善的 SaaS 产品体验
- ✅ 支持多语言和跨境业务
- ✅ 与更多第三方平台集成

3. 我们做什么
3.1 核心功能
链上溯源：
- 多链地址追踪（BTC/ETH/USDT/TRX 等）
- 交易路径可视化
- 资金流向分析
- 关联地址挖掘
- 混币器穿透
- 隐私币标记
智能分析：
- 风险评分系统
- 行为模式识别
- 异常交易检测
- 实体识别与聚类
- 自动化报告生成
风控合规：
- AML/KYC 检查
- 制裁名单筛查
- 交易监控预警
- 合规报告导出
- 审计日志管理
数据可视化：
- 交易关系图谱
- 资金流向图
- 时间轴分析
- 地理分布图
- 统计报表
3.2 技术特色
- 多链支持：覆盖主流公链和 Layer2
- 实时分析：毫秒级响应的链上数据查询
- 深度追踪：支持 100+ 跳的交易路径分析
- AI 赋能：机器学习驱动的风险识别
- 大数据处理：PB 级数据存储和分析能力
3.3 核心算法
混币穿透算法：基于多维特征的概率匹配，追踪 Tornado Cash、Wasabi 等混币器。
风险评分算法：多维度加权评分（0-100 分），评估地址风险等级。
实体识别算法：基于图聚类和机器学习的实体识别。

6. 工作流程
6.1 开发流程
敏捷开发（Scrum）：
Sprint 规划 → 开发 → 代码审查 → 测试 → 发布
    ↑                                    ↓
    └────────── 回顾与改进 ──────────────┘

每两周一个 Sprint：
- 周一：Sprint 规划会
- 每日：站会（10 分钟）
- 周五：代码冻结，准备发布
- 双周：Sprint 回顾会
6.2 Git 工作流
分支策略：
main          - 生产环境
├── develop   - 开发主分支
│   ├── feature/xxx  - 功能分支
│   ├── bugfix/xxx   - Bug 修复分支
│   └── hotfix/xxx   - 紧急修复分支

提交规范：
feat: 新增功能
fix: Bug 修复
docs: 文档更新
style: 代码格式
refactor: 重构
test: 测试
chore: 构建/工具

6.3 代码审查
审查要求：
- 所有代码必须经过审查
- 至少 1 人审查（核心模块 2 人）
- 24 小时内完成审查
- 使用 Pull Request
审查重点：
- 功能正确性
- 代码质量
- 安全性
- 性能
- 可维护性
6.4 发布流程
发布周期：
- 小版本：每两周
- 大版本：每季度
发布步骤：
1. 代码冻结
2. 回归测试
3. 预发布环境验证
4. 生产环境部署
5. 上线验证
6. 监控观察

7. 开发环境搭建
7.1 前置要求
操作系统：
- macOS 12+ 或 Linux（Ubuntu 20.04+）
- Windows 需使用 WSL2
开发工具：
- VS Code 或 IntelliJ IDEA
- Git 2.30+
- Docker 20+
- kubectl
7.2 环境配置
1. 克隆代码：
git clone git@github.com:realtrace/chaintrace.git
cd chaintrace

2. 安装依赖：
# 后端
cd backend
go mod download

# 前端
cd web
npm install

# 算法
cd algorithm
pip install -r requirements.txt

3. 启动本地环境：
# 使用 Docker Compose 启动完整环境
docker-compose up -d

# 或单独启动服务
make dev-up

4. 验证环境：
# 检查服务状态
curl http://localhost:8080/health

# 检查数据库
psql -h localhost -U postgres -d chaintrace

9. 常见问题
9.1 技术相关问题
Q: 如何调试链上数据？A: 使用测试网数据，或在本地搭建模拟链环境。
Q: 数据库连接失败怎么办？A: 检查数据库服务状态、网络连接、防火墙配置。
Q: 如何查看线上日志？A: 使用 Kibana 或 kubectl logs 命令。
9.2 流程相关问题
Q: 如何申请新功能？A: 在飞书任务中创建需求，产品负责人评估后加入 backlog。
Q: 如何发布代码？A: 提交 PR → 代码审查 → 合并到 develop → CI/CD 自动部署。
Q: 遇到 Bug 怎么办？A: 在 Bug 管理表中记录，按严重程度处理。
9.3 团队相关问题
Q: 如何联系团队成员？A: 优先使用飞书，紧急情况下打电话。
Q: 工作时间的安排？A: 核心工作时间 10:00-18:00，其他时间弹性。
Q: 如何请假？A: 在飞书审批中提交请假申请。
